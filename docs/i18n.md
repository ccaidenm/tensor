# Internationalization

Tensor's translations live in `locales/`: one JSON file per locale, with `en.json` as the source of truth. Every string the app displays enters the app through this directory: the English file defines both the wording and the *shape* of the key space, and every other locale must mirror that shape exactly.

## The files

Keys are dot-paths into a nested object. Values are English sentences; named `{placeholders}` interpolate at render time:

```json
{
  "about": {
    "info": {
      "version": "Version {version} · {license}"
    }
  }
}
```

Two rules keep files safe to edit:

- **Never translate or rename keys**: only values. The key path is the contract.
- **Keep `{placeholders}` verbatim**: the app passes those values by name; a renamed token renders literally.

## How the app loads them

The i18n runtime (`src/lib/i18n`) discovers every `locales/*.json` at build time and loads a locale on demand: adding a file is all it takes to register a language. `t()` resolves a dot-path against the active dictionary:

```tsx
t('about.info.version', { version: APP_VERSION, license: LICENSE })
```

If a key is missing from the active locale, `t()` falls back to English; if it's missing from English too, you get the key itself and a one-time console warning. A locale without a file can't be activated at all. Missing translations degrade to English, never to a blank UI.

Switching locales is currently a restart-level preference: the app ships English only, and the language picker lands with the second locale.

## For developers

1. Add the string to `locales/en.json` under the surface's namespace (`about.*`, `editor.*`, …).
2. Replace the literal in the component with `t('your.key', params)` from `@/lib/i18n`.
3. Run the tests: `src/tests/i18n.test.ts` enforces that every leaf of every locale file is a non-empty string and that `en`'s shape is the key space.

Strings migrate as the code that renders them is touched; there's no big-bang extraction. The About panel (Settings → About) is the wired exemplar: everything else still holds literals, and each surface's move to `t()` is its own commit.

| Convention | Why |
|---|---|
| One namespace per surface | Keeps PR diffs reviewable and Weblate contexts obvious |
| Params over concatenation | Word order differs between languages |
| Brand names ("Tensor") stay in code, not in dictionaries | They render everywhere unchanged |

## For translators

Tensor uses [Weblate](https://weblate.org/): the repository is the component, English is the source language, and one locale file is one translation unit.

| What you do | What you never do |
|---|---|
| Translate the **values** of your locale's file | Rename keys or restructure the JSON |
| Keep `{placeholders}` exactly as written | Translate inside the braces |
| Add a locale as `locales/<code>.json` (BCP 47, e.g. `fr.json`, `pt-BR.json`) | Edit `en.json` (it's the source of truth) |

Every pull request runs the key-parity test: your file must mirror `en.json`'s shape or the build fails before anything ships.

## Adding a locale

1. Copy `locales/en.json` to `locales/<code>.json`.
2. Translate the values, keeping keys and placeholders intact.
3. Open a pull request: the loader and the test pick it up with no code changes.
